# 前端性能规范

> 版本：v0.1  
> 类型：前端工程规范  
> 作用域：OpenSpec Workspace


# 1. 文档目的


本文档定义前端应用性能设计、开发和优化规范。


目标：

- 提升页面加载速度；
- 降低资源消耗；
- 优化用户交互体验；
- 指导 AI Coding Agent 进行性能友好的前端开发。


---

# 2. 性能优化原则


## 2.1 性能优先但不过度优化


性能优化应该基于实际问题。


要求：

- 先分析性能瓶颈；
- 再制定优化方案；
- 避免为了优化增加复杂度。


禁止：

没有性能问题时进行无意义优化。


---

## 2.2 用户体验优先


性能优化应该关注用户实际体验。


重点关注：

- 首次加载速度；
- 页面响应速度；
- 操作流畅度；
- 数据加载体验。


---

# 3. 页面加载优化


## 3.1 代码分割


大型应用应该进行代码拆分。


目标：

减少首次加载资源。


方式：

- 路由懒加载；
- 组件异步加载；
- 按功能拆分代码。


示例：

```typescript
const OrderPage = () =>
  import('@/pages/order/OrderPage.vue');
```


---

## 3.2 首屏优化


首屏页面应该优先加载必要资源。


优化方式：

- 减少首屏组件数量；
- 延迟加载非关键资源；
- 避免大量同步请求。


---

## 3.3 资源加载优化


需要关注：

- JS文件大小；
- CSS文件大小；
- 图片资源大小；
- 第三方依赖体积。


避免：

引入未使用的大型依赖。


---

# 4. 组件性能规范


## 4.1 避免无效渲染


组件更新应该基于实际数据变化。


避免：

- 不必要的状态更新；
- 父组件更新导致大量子组件重新渲染。


---

## 4.2 合理拆分组件


大型组件应该拆分。


原因：

- 降低渲染范围；
- 提升维护性；
- 提高复用能力。


---

## 4.3 列表渲染优化


大量数据展示时：

应该考虑：


- 分页加载；
- 虚拟列表；
- 懒加载。


避免：

一次渲染大量 DOM。


---

# 5. 网络请求优化


## 5.1 减少无效请求


避免：

- 重复请求；
- 页面重复加载相同数据；
- 无必要的数据刷新。


---

## 5.2 请求状态管理


请求应该明确处理：


```
Loading

↓

Success

↓

Error
```


避免：

用户不知道当前请求状态。


---

## 5.3 数据缓存


对于适合缓存的数据：

可以使用：

- 前端缓存；
- 请求缓存；
- 服务端缓存。


需要考虑：

- 数据有效期；
- 数据一致性。


---

# 6. 图片资源优化


## 6.1 图片格式


根据场景选择合适格式。


例如：

- WebP；
- SVG；
- 压缩后的图片格式。


---

## 6.2 图片加载


优化方式：

- 图片懒加载；
- 合理尺寸；
- 避免加载超大图片。


---

# 7. CSS性能规范


## 7.1 避免复杂选择器


避免：

过深 CSS 层级。


推荐：

简单、明确的 class。


---

## 7.2 避免重复样式


公共样式应该抽取。


例如：

- 主题变量；
- 设计系统；
- 公共组件样式。


---

# 8. 前端工程优化


## 8.1 依赖管理


新增依赖需要评估：


- 包大小；
- 使用频率；
- 替代方案；
- 长期维护成本。


---

## 8.2 构建优化


需要关注：

- 打包体积；
- 构建时间；
- 环境配置。


---

# 9. 性能监控


应用应该关注：


## 加载指标


例如：

- 首屏加载时间；
- JS加载时间；
- 资源大小。


---

## 运行指标


例如：

- 页面响应时间；
- 长任务；
- 内存占用。


---

## 用户体验指标


例如：

- 页面可交互时间；
- 操作响应速度。


---

# 10. AI Coding Agent 性能规则


AI 修改前端代码时必须考虑性能影响。


修改前读取：


```
delivery/

design.md

+

frontend standards

+

existing implementation
```


分析：

- 是否增加资源体积；
- 是否影响渲染；
- 是否增加请求；
- 是否影响用户体验。


---

AI 不应该：


## 10.1 随意引入大型依赖


新增依赖必须说明：

- 使用原因；
- 体积影响；
- 替代方案。


---

## 10.2 创建低效渲染逻辑


避免：

- 大量重复计算；
- 不必要响应式数据；
- 高频无效更新。


---

## 10.3 忽略性能验证


涉及性能敏感场景时：

需要提供：

- 优化方案；
- 验证方式；
- 测试结果。


---

# 11. 性能检查清单


提交前检查：


```
[ ] 首屏加载无明显问题

[ ] 无重复请求

[ ] 图片资源合理

[ ] 组件渲染合理

[ ] 无明显性能瓶颈

[ ] 新增依赖已评估

[ ] 性能影响已验证
```


---

# 12. 性能优化流程


性能优化应该遵循：


```
发现问题

↓

性能分析

↓

制定方案

↓

实施优化

↓

验证效果

↓

记录结果
```


---

# 13. 与 Change 的关系


性能相关修改必须属于 Change。


例如：

```
优化订单列表加载速度

↓

CHG-ORDER-PERFORMANCE-001
```


Change 中需要记录：


- 当前性能问题；
- 优化方案；
- 优化结果；
- 验证数据。


---

# 14. 总结


前端性能规范用于保证：


```
代码质量

+

用户体验

+

系统稳定性

+

AI开发质量
```


保持一致。


优秀的前端应用应该：

- 加载快速；
- 交互流畅；
- 资源合理；
- 易于维护。
