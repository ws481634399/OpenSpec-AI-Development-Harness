# Spec：用户注册

## §1 背景

当前系统仅支持管理员手动创建账号，用户增长受限。本次需求实现用户自助注册能力，支持邮箱或手机号两种注册方式。

验证码和第三方登录不在本期范围，后续独立 Change 实现。

## §2 用户价值

### 目标用户

**角色：** 未注册访客

**JTBD 场景：**

```
When I 想要使用平台功能（如发布内容、下单购物、参与社区），
I want to 通过邮箱或手机号自助注册账号，
So that 我可以拥有个人空间并使用平台全部功能。
```

**核心需求：**

- 快速完成注册（< 30 秒）
- 不需要等待管理员审批
- 选择自己喜欢的联系方式（邮箱或手机号）

### 价值分析

**直接价值：**

- 用户可自助完成注册，不依赖管理员
- 提供邮箱/手机号双入口，降低接入门槛

**业务价值：**

- 用户增长从人工驱动变为产品驱动
- 收集用户联系方式（邮箱/手机），为后续通知营销打基础

## §3 范围

### Scope In（本期实现）

- 邮箱注册（含格式校验）
- 手机号注册（含格式校验）
- 密码设置（含强度校验：≥8 位，含大小写+数字）
- 重复注册检测（邮箱/手机号已存在 → 提示）
- 注册成功后返回 userId + token（自动登录）

### Scope Out（本期不实现）

- 邮箱验证码发送 → 属于"用户认证"域其他 Story
- 短信验证码发送 → 依赖短信服务集成，后续 Change
- 第三方登录（微信/GitHub） → 独立 Feature
- 用户资料完善（头像、昵称） → 注册后引导，独立 Story
- 密码找回 → 独立 Story

## §4 业务规则

### 数据约束

| 规则名 | 条件 | 结果 |
|--------|------|------|
| 邮箱格式 | 必须符合 RFC 5322 格式 | 不符合 → 400 |
| 手机号格式 | 必须符合 `+<国家码><号码>` 格式，10-15 位 | 不符合 → 400 |
| 邮箱唯一性 | 同一邮箱不可重复注册 | 重复 → 409 |
| 手机号唯一性 | 同一手机号不可重复注册 | 重复 → 409 |
| 邮箱/手机至少一个 | email 和 phone 不可同时为空 | 都空 → 400 |
| 密码长度 | ≥ 8 字符，≤ 128 字符 | 不符 → 400 |
| 密码强度 | 必须包含至少 1 个大写 + 1 个小写 + 1 个数字 | 不符 → 400 |

### 流程约束

1. 注册前不需要验证码（本期）
2. 注册成功后自动生成 Token，返回给客户端
3. 注册后用户状态为 active，可立即使用系统

### 权限约束

- 注册端点为公开端点，不需要认证
- 速率限制：同一 IP 每分钟最多 5 次注册请求

### 异常处理

| 异常场景 | 业务响应 |
|---------|---------|
| 邮箱已注册 | 409 + "邮箱已注册" + 提供找回密码链接 |
| 手机号已注册 | 409 + "手机号已注册" |
| 邮箱和手机号都已注册 | 409 + "邮箱和手机号均已注册" |
| 密码强度不足 | 400 + "密码需至少 8 位，含大小写字母和数字" |
| 网络超时 | 500 + "注册失败，请重试" |

## §6 成功指标

| 指标 | 基线 | 目标 | 度量方式 |
|------|------|------|----------|
| 注册完成率（进入注册页 → 提交成功） | 人工开号无自助数据 | ≥ 80% | 前端埋点漏斗 |
| 注册平均耗时 | 人工开号 > 1 工作日 | < 30 秒 | 后端请求耗时 P95 |
| 注册接口错误率（4xx 中可避免的校验类） | — | < 5% | 接口日志统计 |
