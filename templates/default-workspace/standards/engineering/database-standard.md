# 数据库规范

> 版本：v0.1  
> 类型：工程通用规范  
> 作用域：OpenSpec Workspace


# 1. 文档目的


本文档定义软件项目中数据库设计、变更、迁移和维护规范。


目标：

- 保证数据库结构稳定；
- 降低数据变更风险；
- 保证数据库变更可追踪；
- 使 AI Coding Agent 能够按照统一规则进行数据库相关开发。


---

# 2. 数据库设计原则


## 2.1 数据模型服务于业务


数据库设计应该围绕业务领域展开。


要求：

- 表结构表达明确业务含义；
- 字段命名具有业务语义；
- 避免无意义字段。


例如：

推荐：

```
order_status
payment_time
customer_id
```


避免：

```
status1
value
data
```


---

## 2.2 保持结构简单


数据库设计应该：

- 清晰；
- 可维护；
- 易理解。


避免：

- 过度拆分；
- 复杂关联；
- 无业务价值的数据结构。


---

## 2.3 数据一致性优先


设计时需要考虑：

- 数据完整性；
- 事务边界；
- 并发场景；
- 数据生命周期。


---

# 3. 表设计规范


## 3.1 表命名


表名应该使用具有业务含义的名称。


推荐：

```
orders

order_items

payments
```


避免：

```
table1

data_info

temp_order
```


---

## 3.2 表名格式


推荐：

- 使用小写；
- 使用下划线分隔；
- 使用复数形式。


例如：

```
user_accounts

product_categories
```


---

## 3.3 主键规范


每个业务表应该具有唯一主键。


推荐：

```
id
```


或者：

```
xxx_id
```


例如：

```
order_id
```


---

## 3.4 创建时间和更新时间


业务表建议包含：


```
created_at

updated_at
```


用于：

- 数据追踪；
- 排查问题；
- 数据分析。


---

# 4. 字段设计规范


## 4.1 字段命名


字段名称应该表达业务含义。


推荐：

```sql
payment_status

expired_at
```


避免：

```sql
flag

type

num
```


---

## 4.2 字段类型


选择合适的数据类型。


例如：

金额：

推荐：

```
DECIMAL
```


避免：

```
FLOAT
```


时间：

推荐：

```
DATETIME

TIMESTAMP
```


---

## 4.3 空值设计


字段是否允许为空需要明确。


避免：

- 大量无意义 NULL；
- 使用默认值隐藏业务问题。


---

# 5. 索引设计规范


## 5.1 索引原则


索引应该服务于查询场景。


不要：

- 为所有字段添加索引；
- 创建无实际使用的索引。


---

## 5.2 常见索引场景


适合建立索引：


- 主键查询；
- 高频查询字段；
- 关联字段；
- 排序字段。


例如：

```sql
CREATE INDEX idx_order_user_id
ON orders(user_id);
```


---

# 6. 数据库变更规范


## 6.1 所有结构变化必须通过迁移文件


禁止：

直接手动修改生产数据库。


必须使用：


```
Database Migration
```


---

## 6.2 Migration文件规范


示例：


```
db/migration/

V001_create_order_table.sql

V002_add_payment_status.sql
```


---

## 6.3 Migration要求


每个迁移文件应该：


包含：

- 变更目的；
- 修改内容；
- 执行顺序。


---

# 7. SQL规范


## 7.1 SQL格式


SQL应该保持可读。


推荐：


```sql
SELECT
    id,
    order_status
FROM orders
WHERE id = 1;
```


避免：


```sql
select id,order_status from orders where id=1;
```


---

## 7.2 禁止危险操作


生产环境禁止：


未经验证执行：

```sql
DROP TABLE
```


或：


```sql
DELETE FROM table;
```


---

# 8. 数据迁移规范


## 8.1 小步变更


数据库变更应该：

- 小范围；
- 可验证；
- 可回滚。


---

## 8.2 大字段变更


涉及：

- 大表；
- 大数据量；
- 核心业务表；


需要提供：

- 执行方案；
- 风险分析；
- 回滚方案。


---

# 9. 数据安全规范


数据库设计需要考虑：


## 敏感数据


例如：

- 用户隐私；
- 身份信息；
- 支付信息。


要求：

- 最小化存储；
- 必要时加密；
- 避免日志泄露。


---

## 权限控制


数据库访问应该：

- 最小权限；
- 分环境管理；
- 避免共享账号。


---
