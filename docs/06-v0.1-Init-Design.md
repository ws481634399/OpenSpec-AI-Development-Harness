# OpenSpec AI Development Harness v0.1 Init Design

> Version: v0.1  
> Status: Draft  
> Type: Implementation Design

# 1. 功能概述

## 1.1 功能名称

Workspace Initialization System

命令：

```bash
sdd init
```

---

## 1.2 功能目标

为任意软件项目初始化 OpenSpec AI Development Harness 工作空间。

初始化后，项目具备：

- SDD开发结构；
- 项目知识空间；
- Change管理空间；
- Skill执行环境；
- AI Agent使用规则。

---

# 2. 设计原则

## 2.1 初始化不修改业务代码

原则：

```
implementation/
```

由用户管理。

初始化只创建：

- Harness目录；
- 配置文件；
- 模板文件。

禁止：

- 修改代码；
- 移动代码；
- 重构项目。

---

## 2.2 支持新项目和已有项目

两种模式：

## Greenfield

新项目。

例如：

```
创建一个新的AI商城项目。
```

---

## Brownfield

已有项目。

例如：

```
已有Spring Cloud项目接入OpenSpec。
```

---

# 3. 使用方式

## 3.1 基础初始化

进入项目目录：

```bash
cd my-project
```

执行：

```bash
sdd init
```

---

# 4. 初始化交互流程

## Step 1：欢迎信息

输出：

```
OpenSpec AI Development Harness
Workspace Initialization
Version: v0.1
```

---

# Step 2：选择项目类型

询问：

```
请选择项目类型：
1. 新项目 Greenfield
2. 已有项目 Brownfield
请输入:
```

---

## Greenfield

创建：

```
implementation/
```

作为代码入口。

---

## Brownfield

保留已有代码。

用户选择：

代码是否已经存在：

```
Yes
No
```

---

# Step 3：选择仓库模式

询问：

```
请选择仓库模式：
1. 单仓 Single Repository
2. 多仓 Multi Repository
```

---

# 5. 单仓模式设计

## 5.1 场景

例如：

```
project/
├── backend/
├── frontend/
└── ai-service/
```

或者：

```
一个Git仓库
```

---

## 5.2 生成

```
.sdd/repositories.yaml
```

内容：

```yaml
mode:
 single
repositories:
  - id:
      main-repository
    path:
      implementation/
```

---

# 6. 多仓模式设计

## 6.1 场景

例如：

```
workspace/
├── order-service/
├── user-service/
├── frontend/
```

多个Git仓库。

---

## 6.2 生成

```yaml
mode:
 multi
repositories:
 - id:
     order-service
   path:
     implementation/order-service
 - id:
     frontend
   path:
     implementation/frontend
```

---

# 8. .sdd目录设计

```
.sdd/
├── workspace.yaml
├── repositories.yaml
├── context-rules.yaml
└── version.yaml
```

---

# 8.1 workspace.yaml

记录项目基础信息。

示例：

```yaml
workspace:
 name:
  ai-commerce-platform
 type:
  brownfield
 harness:
  version:
   0.1.0
```

---

# 8.2 repositories.yaml

记录代码仓库。

示例：

```yaml
repositories:
 mode:
  multi
 repositories:
  - id:
      order-service
    path:
      implementation/order-service
```

---

# 8.3 context-rules.yaml

定义AI读取规则。

示例：

```yaml
stages:
 explore:
  read:
   - product/
   - standards/
 design:
  read:
   - standards/
   - product/
   - implementation/
 dev:
  read:
   - delivery/current/
   - implementation/
```

---

# 8.4 version.yaml

记录Harness版本。

示例：

```yaml
harness:
 version:
  0.1.0
```

---

生成：

```

├── sdd/
├── engineering/
└── project/
```

---

## sdd

放置：

OpenSpec标准。

---

等待：

- 知识逆向生成。

```yaml
features: []
```


---

# 12. Implementation初始化

根据模式：

创建：

```
implementation/
```

## 已有项目

不移动。

```

implementation/
```

# 18. v0.1范围限制

当前版本不包含：

## 不自动分析代码

原因：

属于：

knowledge reverse。

---

## 不自动生成Feature

原因：

属于：

sdd-feature-tree。

---

## 不接入模型

原因：

由：

Trae/Cursor/Claude Code
负责。

---

# 19. v0.1验收标准

完成后：

开发者可以：

## 新项目

```
sdd init
↓
开始开发
```

---

## 旧项目

```
sdd init
↓
导入代码
↓
knowledge reverse
↓

```

## AI Agent

能够读取：

```
standards
product
delivery
skills
```

并按照：

```
SDD Workflow
```

参与开发。

---

# 20. 总结

`sdd init` 是 OpenSpec Harness 的入口能力。

它负责：

```
创建工作空间
↓
加载工程规范
↓
建立知识边界
↓
准备AI开发环境
```

它不是代码生成工具。

它是：

> AI 原生软件工程环境的初始化器。
